# 商城订单转物流订单实施方案

## 目标与成功标准

本次只调整商城订单与物流订单之间的业务链路：

1. 客户提交商城订单后，订单进入 `待确认`，不会直接生成物流订单。
2. 商城管理员核对商品、收件人和金额后，执行 `确认订单`，订单进入 `已确认`。
3. 只有 `已确认` 的订单可以进入 `提交物流` 页面。
4. 管理员补齐寄件人、物流路线、申报价值、证件号、重量和尺寸等物流必需信息后提交。
5. 后端成功创建物流订单后，商城订单变为 `已提交物流`，并保存物流订单 ID 和单号。
6. 生成的订单可在物流后台订单列表与详情页查询，状态从物流后台既有的 `待审核` 流程开始。
7. 重复点击、刷新或重复请求不会生成第二张物流订单。

## CEO Review：产品路径

### 核心路径

```text
客户提交商城订单
        ↓
商城后台：待确认
        ↓ 人工确认
商城后台：已确认
        ↓ 补齐物流资料并提交
物流后台：生成待审核订单
        ↓
商城后台：已提交物流，并显示物流单号和查看入口
```

`确认订单` 与 `提交物流` 必须是两个动作。商城订单中只有收件人与商品快照，物流订单还需要寄件人、路线、重量尺寸、人民币申报价值和证件号；在这些数据缺失时自动生成物流单，会产生无法审核或申报错误的订单。

### 管理员界面

- `待确认`：显示 `确认订单`、`取消订单`。
- `已确认`：显示 `提交物流`。
- `已提交物流`：显示物流单号及 `查看物流订单`。
- `已取消`：不允许确认或提交物流。
- 提交物流页面自动带入收件人及商品名称、数量，管理员只填写物流侧缺失信息。
- 商城币种不自动换算为人民币；每项商品的人民币申报单价由管理员明确填写，避免静默使用错误汇率。

### 边界情况

- 待确认、已取消订单不能提交物流。
- 已提交物流订单再次请求时直接拒绝，不重复创建。
- 商品后来下架、修改或删除，不影响订单中的商品快照。
- 物流创建失败时，商城订单保持 `已确认`，管理员可修正后重试。
- 字段校验失败时显示明确错误，不静默失败。
- 本次不包含自动交给 CDEK/承运商；新物流单仍进入物流后台现有的人工审核流程。
- 本次不包含批量提交、自动汇率换算或在线支付。

## Eng Review：技术方案

### 状态与数据

沿用商城订单状态：

- `PENDING_CONFIRMATION`
- `CONFIRMED`
- `LINKED_TO_LOGISTICS`
- `CANCELLED`

商城订单增加可选关联字段：

- `logisticsOrderId`：用于跳转物流后台详情。
- `logisticsReferenceNo`：用于列表和详情展示物流单号。

状态只允许：

```text
PENDING_CONFIRMATION → CONFIRMED
PENDING_CONFIRMATION → CANCELLED
CONFIRMED → LINKED_TO_LOGISTICS
```

### 后端数据流

新增管理员专用接口：

```text
POST /admin/shop/orders/:id/logistics
```

请求只接收管理员需要补充的数据：

- 路线
- 寄件人
- 各商品人民币申报单价
- 税号或证件号
- 重量、长宽高、包裹数量

收件人与商品名称、数量由服务端从商城订单快照生成，不信任浏览器重复提交这些数据。桥接服务执行：

1. 校验管理员权限。
2. 读取商城订单并校验状态为 `CONFIRMED`。
3. 校验尚未关联物流订单。
4. 组合物流订单 DTO，调用现有 `LogisticsService` 创建物流订单。
5. 创建成功后持久化商城订单的物流 ID、单号及 `LINKED_TO_LOGISTICS` 状态。
6. 返回商城订单和物流订单摘要。

若物流创建失败，不修改商城订单状态。若关联保存失败，桥接服务执行补偿处理，避免留下无法追踪的重复物流单。

### 最小文件范围

- `packages/shared`：补充商城订单物流关联字段。
- `apps/api/src/shop`：新增桥接 DTO、服务、状态校验及单元测试。
- `apps/api/src/shop/admin-shop.controller.ts`：增加管理员提交物流接口。
- `apps/api/src/shop/shop.module.ts`：接入现有物流模块。
- `apps/web/app/admin/shop/orders/[id]`：增加状态动作和关联结果展示。
- `apps/web/app/admin/shop/orders/[id]/logistics`：新增物流资料补全表单。
- 相关翻译与局部样式文件。

不重构现有商城、物流页面，不改变客户下单字段，也不修改无关业务。

### 风险与约束

- 当前物流模块使用既有的内存数据仓库，服务重启后新建物流订单会丢失；这不是桥接逻辑特有的问题。为保证本功能真正可用，本次会把物流订单创建及后续状态修改接入现有项目的本地持久化方式，并保留示例订单初始化行为。
- 商城订单与物流订单不是同一数据库事务，桥接服务需要使用唯一关联检查和失败补偿保证重复请求安全。

## 验证计划

### 自动测试

- 待确认订单提交物流：拒绝。
- 已取消订单提交物流：拒绝。
- 已确认订单提交物流：生成物流订单并建立关联。
- 同一订单重复提交：不生成第二张物流订单。
- 物流服务失败：商城订单仍为 `CONFIRMED`。
- 缺少申报价值、寄件人或包裹参数：返回可见校验错误。
- API 鉴权：非管理员不能调用。
- `npm run build` 通过。

### 浏览器验收

1. 客户提交一张商城订单。
2. 商城后台能查询到 `待确认` 订单。
3. 管理员确认后出现 `提交物流`，但此时物流后台没有新订单。
4. 补齐物流资料并提交。
5. 商城订单显示 `已提交物流` 和物流单号。
6. 点击入口能打开物流后台对应订单。
7. 刷新页面及重启服务后，两侧订单和关联仍存在。
